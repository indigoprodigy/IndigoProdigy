# Public Engineering Portfolio Roadmap

This roadmap describes public-facing work that can be demonstrated without exposing private UniversoulCo operations, unreleased IP, or internal infrastructure.

## Track A — Agent governance reference

- [x] Publish a scoped governance standard.
- [x] Publish emergency-stop requirements.
- [x] Publish production-readiness gates.
- [x] Publish cost and ROI ledger schema.
- [x] Build a small policy-evaluation reference library with unit tests.
- [ ] Add CI evidence from a successful GitHub Actions run.
- [ ] Add threat model and misuse-case tests.
- [ ] Add signed policy examples and structured audit event schema.

## Track B — Creative technology

- [ ] Expand standalone visual experiments into accessible, documented browser demos.
- [ ] Add keyboard and screen-reader checks.
- [ ] Provide screenshots or short screen recordings for reviewed demos.
- [ ] Document original design decisions and implementation tradeoffs.

## Track C — Engineering quality

- [ ] Add contribution guide and issue templates.
- [ ] Add dependency and secret scanning after reviewing workflow permissions and cost.
- [ ] Add release/versioning policy.
- [ ] Add reproducible local development instructions.
- [ ] Add architecture decision records for meaningful design choices.

## Publication gate

Every new artifact must pass the repository's ownership, confidentiality, technical safety, and publication review standards. Do not publish proprietary systems merely to make the portfolio appear more advanced.
